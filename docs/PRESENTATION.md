# Материалы для презентации

Живой журнал: что сделано для точности и продукта, с цифрами и тем, как это рассказывать.
Обновляется после каждого шага. Детали экспериментов — в `reports/`.

Питч по ТЗ — до 7 минут: концепция → архитектура пайплайна → живое демо → метрики Top-1/Top-5 → функция после поиска → выводы.

## Ключевые тезисы (коротко, для слайдов)

- **Подход**: предобученная SigLIP 2 без дообучения → каталог индексируется в pgvector → распознавание = векторный поиск ближайшего эталона. Новое вино добавляется без переобучения: одно фото → один вектор в базу.
- **Условие one-shot**: на каждое вино ровно одно эталонное фото; поле — крупный план этикетки у полки, эталон — студийное фото бутылки.
- **Главная сложность**: серии этикеток одной винодельни (разница — сахар, цвет, год). 106 из 107 самых похожих пар эталонов — одна винодельня.
- **Честная оценка**: только однозначно сопоставленные позиции; проблемные записи (спорные фото, двойники) выявлены автоматически и вынесены из метрики.
- **UX под ТЗ «одна карточка без выбора»**: сервис знает, когда он уверен. Когда говорит «уверен» — прав в 96 % случаев (синтетика); иначе честно показывает варианты или «нет в каталоге».
- **Скорость**: ~0.75 с на запрос на ноутбучной RTX 3050 Ti (ТЗ — до 3 с), из них нейросеть ~0.1 с.

## Метрики (сводка — обновлять)

Синтетический тест: 2 «полевых» фото на каждое вино (крупный план этикетки / бутылка, перспектива, фон, свет, блик, размытие, JPEG), ~3800 запросов, двойники исключены.

## Журнал улучшений

### 1. Отбор однозначных позиций каталога
- **Проблема**: в CSV хранится исходное имя фото, в выгрузке Strapi — переименованные файлы с хешем; часть фото привязана к нескольким вин (спорные соответствия).
- **Что сделали**: сопоставление имён с транслитерацией и нормализацией; позиция берётся, только если фото принадлежит одному вину и находится ровно один файл.
- **Итог**: 1964 из 2103 вин; 139 исключены с причиной (`data/catalog/excluded.csv`): 26 — одно фото на несколько вин, 67 — файл не найден, 46 — несколько разных файлов.
- **Как рассказать**: «Сначала навели порядок в данных: автоматически нашли и отложили спорные записи, чтобы метрика была честной».

### 2. Нормализация фото (подсказка кейсодержателя)
- EXIF-поворот, прозрачный фон → белый, обрезка белых полей, приведение к квадрату без обрезки этикетки. Одна и та же функция для эталонов и фото пользователя.
- **Как рассказать**: «Фото с телефона и студийное фото приводятся к одному виду до нейросети».

### 3. CV baseline: SigLIP 2 + pgvector
- Эталон → вектор 1152 чисел → pgvector; запрос → вектор → ближайшие по косинусу.
- Top-1 60.4 % / Top-5 80.7 % (синтетика). Отдаёт Top-5 со скором и отрывом Top-1 от Top-2.

### 4. Уверенность и «нет в каталоге»
- `status`: `confident` (отрыв ≥ 0.03) → одна карточка; `uncertain` → карточка + раскрытые варианты «Не то вино?»; `not_found` (скор < 0.72) → «точного совпадения нет» + похожие вина.
- **Как рассказать**: «Экран вариантов появляется только когда модель сомневается; вина вне каталога не выдаются за чужие».

### 5. Двойники в каталоге
- **Находка**: 33 группы / 67 вин с одинаковым эталоном (косинус ≥ 0.99): одно фото на разные вина (Az Abrau «Баяншира» белое и «Мадраса» красное) или одно вино, заведённое дважды («Императорское брют» и «Удельное Ведомство Императорское белое брют»).
- **Что сделали**: автоматический поиск (`find_twins.py`), в индексе остаются, из основной метрики исключены.
- **Как рассказать**: «Никакой алгоритм по картинке не различит вина с одинаковым фото — это проблема данных, мы её нашли и показали. Рекомендация платформе — заменить эталоны».

### 6. Несколько векторов на вино + смешанный скор
- **Проблема**: пользователь снимает крупный план этикетки, в каталоге — бутылка целиком. Масштаб разный.
- **Что сделали**: для каждого вина индексируем 3 вида — бутылку и две зоны этикетки (30–70 % и 45–95 % высоты). Скор вина = 0.5 · сходство с бутылкой + 0.5 · лучшее сходство с зоной этикетки.
- **Эксперимент, который стоит показать**: просто «лучший из видов» почти не помог (Top-1 +0.9, Top-5 −1.3): помогал на крупных планах (+7.6), но мешал на снимках бутылки (−5.6) — чужие этикетки случайно совпадали. Смесь 50/50 улучшила оба типа снимков.
- **Итог**: Top-1 60.4 → 65.2 %, Top-5 80.7 → 85.8 %, Top-10 → 90.2 %, точность уверенных ответов 90.8 → 96.0 %. На реальных фото: вино вне каталога (Табия) теперь корректно «не найдено».
- **Как рассказать**: «Научили систему смотреть не только на бутылку, но и на этикетку крупно — как это делает человек у полки».

### 7. Интерфейс в стиле «Своё вино»
- Сканер (камера/галерея) → карточка: фото, винодельня, регион, сорт, категория, цвет, описание; «Не то вино?»; «Похожие вина» (по визуальному сходству эталонов).
- Палитра, шрифт Playfair Display и скругления сняты с vino-svoe.ru.

## Находки в данных (для слайда «что мы узнали о каталоге»)

- 139 из 2103 позиций нельзя однозначно связать с фото.
- 67 вин имеют эталон-двойник; часть — явные дубли одного вина под разными slug (разные форматы импорта).
- У части вин эталон — не бутылка, а постановочное фото с бокалом.
- 962 из 1964 вин имеют визуально очень похожего «соседа» (косинус ≥ 0.9) — почти всегда той же винодельни.
